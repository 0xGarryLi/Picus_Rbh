Evaluation before optimization.

Candidate routes are compared only after they pass the same acceptance criteria. Benchmarks must specify source versions, evaluation method, baseline parameters and whether shadow execution overhead was included.

Privacy by design.

Raw user prompts, credentials and private intermediate outputs should not be public or sent to unapproved providers. The roadmap includes local redaction and per-task data retention rules before any real customer data is processed.

Wallet connection.

The site supports EVM wallet connection using an injected wallet provider. It only requests account access. It does not request signatures, token approvals, transactions, or a network switch. No contract interactions are enabled.

Frequently asked questions.

Does PICUS currently optimize live agents?

Not yet. This website is a product concept and interactive presentation; the simulator uses example data.

Will every shadow run be cheaper?

No. A second execution has its own expense. Savings depend on task structure and whether a reusable or less costly valid route can be found.

What is the token for?

Planned eligibility for lower PICUS service prices while holding PICUS. No tiers or tokenomics are finalized.

Is there a deployed PICUS contract?

No verified contract address has been supplied. The site deliberately does not display one.

Why Robinhood Chain?

The long-term direction includes EVM-compatible token benefit verification, potentially on Robinhood Chain. The comparison engine itself works offchain.
